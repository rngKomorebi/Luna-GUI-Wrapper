luna_gui_wrapper.functions.timewalk module

Timewalk post-processing: measure the timewalk curve from the clusters in the file itself and add timewalk-corrected times to its tables.

No TDC or test pulses are needed. All pixels of one cluster fired at the same moment, so their spread in ToA is timewalk plus jitter. The pixel with the largest ToT (the one tpx3dump/tpx4dump report as ctot, whose ToA is ctoa) has the least timewalk and serves as the clock:

dt = toa(hit) - ctoa(its cluster) vs. ToT(hit)

Only clusters with ctot >= ctot_cut take part, so the reference itself walks little. Per ToT bin the peak of dt is found with an iterated 3-sigma truncated mean (robust against the flat background of pile-up hits, and unlike a median not stuck to the 1.5625 ns ToA grid). The result is one curve per file, delay(ToT), and every time is corrected by it:

toa_tw = toa - delay(tot) ctoa_tw = ctoa - delay(ctot)

The corrected times become the last field of the tables themselves – Clusters/ctoa_tw, and PixelHits/toa_tw on request – and the curve is kept as /TimewalkCurve. An HDF5 compound dataset has a fixed dtype, so the first run on a file rewrites it once (into a temporary file beside it, swapped in only when complete); later runs update the field in place.

Correcting each pixel on its own means the reference’s own walk drops out of any time difference. The curve is relative to the high-ToT limit; the constant offset to true arrival time is unknowable without an external reference and does not matter for time differences.

Qt-free. h5py, numpy and pandas are imported inside the functions that need them, so importing this module needs none of them.

luna_gui_wrapper.functions.timewalk.add_timewalk_columns(path, ctot_cut_ns=1000.0, pixel_hits=False, max_hits=50000000, detector=None, log=None)[source]

Measure this file’s timewalk curve and add corrected times to its tables.

Clusters gets a last field ctoa_tw; with pixel_hits, PixelHits gets toa_tw too. Both are in the table’s own ticks. The curve is stored as /TimewalkCurve. A table that already carries the field from an earlier run is updated to the new curve, whatever pixel_hits says, so it never goes stale.

Adding a field means rewriting the file once: it is written to a temporary file beside the original and swapped in only when complete, which needs free space for one more copy of the file. Later runs update the fields in place.

Returns a summary dict, and raises on anything wrong.
