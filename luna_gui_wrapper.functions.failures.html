luna_gui_wrapper.functions.failures module

Why a converter run failed, and what to change before running it again.

Qt-free. The GUI hands over the end of the converter’s output plus the job’s paths; diagnose() picks the known cause out of it. A cause tied to the current settings (an output name that is too long) can be checked again later with still_fails(), so a rerun can warn when nothing has been changed yet.

luna_gui_wrapper.functions.failures.diagnose(lines, code, dst=None, src=None, ctx=None, err='') → Failure[source]

Name the cause of one failed run.

lines: the converter’s last output lines (plus any error lines seen earlier); code: its exit code (-1 if it never ran); err: a message from the GUI side when there is no exit code to go on.

Length of the file name as the stricter of the two file systems counts it: characters for NTFS, UTF-8 bytes for Linux.

luna_gui_wrapper.functions.failures.still_fails(kind, dst) → bool[source]

Would a cause tied to the settings hit again with the job as it is now? Only the name length can be checked ahead of a run; anything else is left to the rerun itself.
