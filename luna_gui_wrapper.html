luna_gui_wrapper package

Luna GUI Wrapper – Qt 6 (PySide6) front end for ASI Luna’s tpx3dump (Timepix3) and tpx4dump (Timepix4).

Browse to the data, let the GUI work out the names, and run the whole batch, instead of typing tpx3dump / tpx4dump process -i … -o … once per file.

This program does not contain, modify, decompile or redistribute any part of Luna. It runs the unmodified Luna executables as subprocesses through their documented command line interface.

The TDC helpers are Qt-free and importable on their own, e.g. from a notebook:

import luna_gui_wrapper as g g.read_tdcs(“run.hdf5”) # the edges, deduplicated g.add_tdc_columns(“run.hdf5”, “TDC1Rising”) # write the columns df = g.read_with_tdc(“run.hdf5”, “Clusters”) # frame with the TDC columns

and so are the timewalk helpers (no TDC needed; measured from the clusters):

g.add_timewalk_columns(“run.hdf5”, ctot_cut_ns=1000) # curve + ctoa_tw df = g.read_with_timewalk(“run.hdf5”, “Clusters”) # frame with ctoa_tw curve = g.read_timewalk_curve(“run.hdf5”)

Importing the package does not import PySide6; only the GUI modules do.

luna_gui_wrapper.add_tdc_columns(path, reference='TDC1Rising', log=None)[source]

Write row-aligned TDC columns into an existing tpx3dump HDF5.

Adds /PixelHitsTDC and /ClustersTDC beside the datasets they describe, each row i carrying the trigger that row i of the source belongs to. The originals are never rewritten: an HDF5 compound dataset has a fixed dtype, so a genuine extra field would mean recreating the whole thing, and these files are the only copy of the measurement. Readers join the two, which read_with_tdc() below does.

Returns {dataset name: summary dict}, and raises on anything wrong.

luna_gui_wrapper.add_timewalk_columns(path, ctot_cut_ns=1000.0, pixel_hits=False, max_hits=50000000, detector=None, log=None)[source]

Measure this file’s timewalk curve and add corrected times to its tables.

Clusters gets a last field ctoa_tw; with pixel_hits, PixelHits gets toa_tw too. Both are in the table’s own ticks. The curve is stored as /TimewalkCurve. A table that already carries the field from an earlier run is updated to the new curve, whatever pixel_hits says, so it never goes stale.

Adding a field means rewriting the file once: it is written to a temporary file beside the original and swapped in only when complete, which needs free space for one more copy of the file. Later runs update the fields in place.

Returns a summary dict, and raises on anything wrong.

luna_gui_wrapper.read_tdcs(path)[source]

The deduplicated TDC edges as a DataFrame, with decoded type and seconds.

The direct equivalent of ASI’s read_tdcs.py.

luna_gui_wrapper.read_timewalk_curve(path)[source]

The stored /TimewalkCurve as a DataFrame; its attrs carry the settings.

luna_gui_wrapper.read_with_tdc(path, which='Clusters', limit=None, reference=None)[source]

One DataFrame of which with the TDC columns joined onto it.

Uses the stored /…TDC dataset when add_tdc_columns() has written one; otherwise tags on the fly from /TDCEvents, so this also works on a file straight out of tpx3dump. Passing reference forces the on-the-fly path, which is how you look at a different edge without rewriting the file. tdc_type comes back as the readable name and tdc_dt_s as seconds, both derived here rather than stored.

luna_gui_wrapper.read_with_timewalk(path, which='Clusters', limit=None)[source]

One DataFrame of which with the corrected time and the correction.

ctoa_tw / toa_tw come straight from the table when the field is there; otherwise (PixelHits written without the per-hit option) they are computed from /TimewalkCurve, to the same values. timewalk_ns (what was subtracted) is added either way.
